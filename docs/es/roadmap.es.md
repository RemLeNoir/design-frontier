# Hoja de ruta después de 1.0

Design Frontier 1.0 establece el formato versionado, el catálogo, el motor de composición, los plugins, las migraciones, los adaptadores de agente, los exportadores, las comprobaciones de integridad, el linting de deriva y la suite de conformidad.

## 1.1

- reglas configurables de inclusión/exclusión de fuentes para los escaneos de deriva;
- formatos de token más ricos para Android e iOS;
- salida JSON para cada comando;
- generación de informes de procedencia del catálogo;
- exportación de inventario de componentes.

## 1.2

- adaptador opcional de documentación de Storybook;
- plugin opcional de línea base visual de Playwright;
- anotaciones de pull request para validación y deriva;
- alias de catálogo y migraciones de deprecación.

## Investigación para 2.0

- snapshots de catálogo firmados por paquete;
- especificación de implementación canónica neutral respecto al lenguaje;
- adaptadores de evidencia visual que sigan siendo seguros en materia de copyright;
- packs de política de organización;
- sincronización bidireccional de tokens con herramientas externas seleccionadas.

El núcleo seguirá siendo neutral respecto al framework y capaz de funcionar sin conexión.
